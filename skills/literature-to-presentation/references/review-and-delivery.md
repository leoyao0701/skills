# 复核、迭代与交付

## 三种检查分开完成

### 事实与来源

核查引文逐字准确、版本与页码一致、译文身份明确、时间范围正确、作者及作品对应、引用范围不超过实际取得材料。优先回查高影响命题和疑点，但不能把抽样检查报告为逐句全文核验。

### 论证与视觉

逐页读正文后再看布局。检查比较双方是否回答同一问题；分类项是否同层；因果是否有依据；条件和例外是否保留；原书、后续研究和讲者推论是否能区分。将每一种视觉组件隐含的关系与实际文本对照。

独立审阅者的任务可以是：“阅读实际页面与来源，指出实质错误、证据范围不足和视觉关系歧义，提供页码、依据及可执行修改；无需为了提出意见而改写所有页面。”报告应允许“未发现问题”，并区分必须修正与可选优化。

### 最终渲染

在交付的最终文件上检查每页，不只检查源数据、抽样页或缩略图。自动检测与人工阅读配合：

- 页面边界、溢出、遮挡、截字与异常留白；不要只测容器，要检查实际文字边界。
- 中文及英文专名字号、换行、字重、标点、行距和投影可读性。
- 图片已加载，比例与图注正确；矩阵的行列和跨格说明仍然对应。
- 页面编号、目录、讲稿跳转、备注及主题映射一致。
- 若交付 PPTX，检查导出包、字体、原生表格/图形及导出后的逐页渲染。
- 声称离线可用时，在无远程依赖的条件下验证；声称时长适配时，记录实际演练或保守的估时依据。

## 修订闭环

每次用户反馈先转为可检查的要求，再动手：

| 反馈 | 要检查的对象 | 有效修订 |
|---|---|---|
| “内容太空、只有一两句” | 定义、条件、案例经过是否缺失 | 补足证据支持的内容，必要时拆页 |
| “语言跳脱” | 口号、夸张判断、隐喻、跳步推论 | 用具体概念、完整判断与限定替代 |
| “像故意引用” | 引文是否承担论证、归属是否机械重复 | 保留有解释价值的原文，减少引述式开头 |
| “视觉不对应逻辑” | 编号、分组、轴、箭头和嵌套的含义 | 重新判定关系，再修改组件 |
| “第一次出现难理解” | 专名、理论归属、相似译词 | 英文首现与简短定义，避免百科式扩写 |

同步修改演示正文、讲稿、备注、来源索引和内部审计记录。更换来源时检查旧 URL 和错误版本是否仍残留。保留可回退版本在工作区，输出目录突出当前交付物，避免旧版混入打包文件。

## 把经验整理成 skill 时

提炼会改变下一次决策的规则，不记录所有操作日志。区分三类经验：

- **通用可靠性要求**：引用必须有准确定位，视觉不能制造未经支持的关系。
- **本用户偏好**：严谨中文、内容充分、原文与讲稿宽幅对照、投影页减少注释。用默认或条件规则保留，不宣称适用于所有演示。
- **本项目约束**：具体书目、25分钟、三部分、34页、文件名、机器路径。只作为有用示例，不固化为以后任务的必需结构。

仓库发布只包含复用所需内容。不要把研究资料夹、受限原文、访问凭据或生成缓存顺手提交。提交前检查暂存差异，确认仓库、分支、可见性和作者身份符合用户指示；正常推送，不为方便覆盖远端历史。

## 最终说明

用简短文字说明交付物、实质修正及实际验证范围。提供当前文件和必要来源入口；存在未解决的证据限制时准确说明。不要把“生成成功”“通过几何检测”或“另一 agent 看过”写成内容绝对正确的保证。
