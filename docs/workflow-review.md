# 文献演示工作流程复盘

本轮优化依据实际制作与修订中出现的返工，不重新研究原项目的文献。目标是减少重复读取和无效生成，同时保留用户要求的内容深度与全文核查范围。

## 反复出现的问题与处理

| 观察到的问题 | 为什么导致返工 | 本次规则调整 |
|---|---|---|
| 一次读取多个长文件，输出截断后又整包重读 | 已读内容再次进入上下文，缺失部分仍难定位 | 先搜索定位，按章节读，截断只补缺失范围；保存已验证的路径与页码 |
| 旧生成入口读取旧版本 | 生成动作成功，但最新修订被覆盖 | 修改前确认内容定稿、当前文件和生成入口的输入 |
| 正文、备用列、展开内容和讲稿存在多份副本 | 改了可见页面，其他字段仍保留旧观点 | 内容只维护一份；重复展示由它生成，按实际引用关系同步 |
| 逐字引文无误，概括却改变了作者立场 | 将“必要”写成“可选”，或将“可能”写成“必然” | 核对上下文与结论，保留强度、量词、条件和结果；将作者主张与评价分开 |
| 并列分类被画成步骤，支持关系被画成因果 | 美化后的组件额外引入了未经论证的关系 | 先用一句话说明关系，再选组件；箭头与编号作为命题审查 |
| 审校意见混入课堂文字 | 正文出现面向编辑的说明，导出后还要重写 | 在导出前单独检查面向听众的语言，审校记录不进入产品正文 |
| 自动同步检查比较隐藏标签与导出内容 | 将非展示字段当成遗漏，触发无效排查 | 明确比较对象：实际正文、表格、备注及约定展示内容 |
| 小修改反复触发全套导出与人工检查 | 未改变的研究内容、页面与格式被反复处理 | 按改动影响范围重查；工具必须整体渲染时，识别变化页并保留可验证的旧检查 |
| 讲稿不断追加整页正文 | 材料越来越长，旧文案与新文案并存 | 保留实质讲解；生成内容不追加到自身，主讲与补充分开 |

这些规则不意味着忽略整体一致性。修改一页的命题仍可能影响结论和讲稿；调整全局字体可能影响全部页面；用户要求全文复核时仍须通读全文。

## 仓库结构调整

- 合并原 `review-and-delivery.md` 与 `working-records.md`，形成 `incremental-workflow.md`，将记录字段、修改范围、同步和验收放在同一条工作线上。
- 缩短 `SKILL.md`，通过任务类型指向相关章节，不要求每轮读取全部规则。
- 保留证据核查与视觉关系表，增加命题强度和面向听众的语言检查。
- 扩展中文 README，说明使用方式、文件结构、输出范围和维护原则。
- 本复盘放在 `docs/`，不占用每次调用 skill 的默认上下文。测试项目与研究成果不进入技能仓库。

## 可以测量的变化（首次优化快照）

以下字符数对应提交 `5515f24`，不包含后续的跨模型适配与打包内容。

按 UTF-8 文本解码后的字符数计算，包含标题、Markdown 与入口元数据；不包含 README、界面元数据和本复盘。

| 范围 | 修改前 | 修改后 |
|---|---:|---:|
| 入口 `SKILL.md` | 2,353 字符 | 1,171 字符 |
| 入口与全部参考文件 | 8,860 字符 | 7,925 字符 |
| 参考文件数量 | 4 | 3 |

入口字符量减少约 50%，全部规则字符量减少约 11%。这是文件读取体积的变化，不是实际 token 账单；没有完整的调用计量，不能据此声称节省了同等比例的 token。实际收益还取决于任务类型、条件性读取和是否避免重复工具调用。

不以压缩字符数为唯一目标：有必要保留的命题强度、证据范围和视觉关系判断，应当继续提供。

## 验证范围

技能格式与内部链接检查通过。独立的虚构三页项目测试已完成实际文件修改：

- 保留逐字引文，修复将必要条件解释为可选路径的概括，并区分必要与充分条件。
- 改正连续箭头，联动修正受影响的结论页及讲稿，保留第一页和已确认的顺序。
- 识别旧生成入口，使用当前内容定稿；只交付约定的 HTML 与 Markdown 讲稿，文件同步检查通过。
- 本地 HTML 被浏览器安全策略阻止打开，因此没有完成视觉渲染验收；未绕过限制，也未把内容检查表述为视觉检查通过。

首轮测试同时暴露：执行者虽然跳过了无关研究与导出阶段，仍读取了三份参考文件全文。因此入口又增加了“先按标题定位，只读取相关章节”的具体步骤。随后以单页局部视觉修改进行第二次测试，单独检查读取范围与修改范围。

第二次测试只读取了视觉关系表及增量流程中的当前状态、修改范围和验收章节，未读取证据核查文件。产物将误导性的先后箭头改为三个平级组件，原有正文全部保留，讲稿逐字节未变；没有外部研究或额外格式。静态检查通过后停止。该案例明确不要求浏览器渲染，因此没有据此声称视觉验收完成。

该测试不等于对真实长篇文献、扫描件 OCR、所有演示格式或所有模型表现的全面验证。今后仅根据可复现的行为问题继续调整规则，避免不断叠加未经验证的例外。

## 原项目的工具与迁移边界

以下根据原项目的生成脚本与检查记录核对。它们不是这个 skill 文件夹的一部分，也不是要求每位使用者逐项安装的固定清单。

| 原项目使用的能力 | 当时的用途 | 当前仓库是否包含？迁移时怎样处理？ |
|---|---|---|
| 系统提供的 `presentations` skill 及其辅助程序 | 字体选择、PPTX 定稿、文件结构与布局检查 | 不包含。需要相同环境或具备相应功能的演示制作工具；只做 HTML 时不要求它 |
| `@oai/artifact-tool` 与配套 Node.js/Python 运行环境 | 创建可编辑 PPTX、重新读取最终文件并渲染检查 | 不包含。不能假定其他人的 Codex 已有这个包；使用别的导出工具须重新检查结果 |
| `pypdf`、`pypdfium2` 和 macOS Vision OCR | PDF 提取、页图处理及扫描件文字识别 | 不包含。可用其他 PDF/OCR 工具替代；macOS 专用部分不能直接移到其他系统 |
| 联网检索与浏览器工具 | 查论文、史实和图片，读取页面及检查 HTML | 不包含，由使用者的 AI 环境提供 |
| 为原项目编写的内容整理、HTML 生成、讲稿同步与表格修正脚本，以及本机中文字体 | 把具体内容转成文件，协调格式与版式 | 不包含。它们带有原项目数据和环境假设；复现同样的制作链还需要整理为可移植的实现 |

此外，`skill-creator` 用于创建、校验这份 skill；`openai-docs` 用于核对安装说明。二者属于技能维护时使用的辅助能力，不是制作每一份文献报告的前置依赖。

因此，**“可以复用流程”与“可以在另一台机器复现整条制作链”是两个不同的交付标准；当前仓库达到的是前者，并有小规模行为验证。**它尚未提供固定的跨平台导出器、自动环境配置或从材料到成品的完整复现示例。安装成功只能证明技能可被加载，不能证明所有输出能力已经就绪。

## 跨模型复用的补充

本轮明确以迁移工作方法为目标，不要求复刻原项目的工具链。技能源增加了按能力执行的约定：材料读取、联网、文件输出和渲染分别处理；工具可替换，证据范围与交付标准不变。

提供两种加载方式：目录式 Skill 保留按需读取；自动合并的 Markdown 文件包含全部参考规则，供没有原生 Skills 功能的模型使用。打包程序只依赖 Python 标准库，普通使用者可直接取用生成文件，无需运行程序。

已完成以下验证：

- 合并程序连续生成相同文本，包含全部参考规则，不残留需要另行读取的参考文件链接。
- 在隔离副本中改动技能源后，检查模式能发现合并版过期，且不改写文件；重新生成后恢复一致。
- 分享包中的文件与源文件逐字节相同；相对路径可用，未带入本机个人路径或原项目资料。
- 独立执行者仅读取合并指令，在不使用联网、文件写入或渲染的模拟场景中，依据虚构摘录交付了完整 HTML 源码和详细讲稿。输出保留“可能”等限定，三个分析方面平级呈现，并说明没有生成附件或完成浏览器验证。

最后一项仍由现有模型完成，是加载方式与能力适配测试，不是多模型性能对照。跨模型的效果一致性、不同客户端的安装过程和各类 PPTX 工具仍需分别实测，不能由文件打包成功推定。
